# 02. 与 DeepSeek V4 Flash 类“大任务 agent rollout”的本质差别

## 2.1 对照表

| 维度 | **常规模板 LLM agent**（DeepSeek V4 Flash 类） | **reap-mcts-lean v1/v2** |
|---|---|---|
| 动作空间 | 自由文本/JSON 工具调用（生成器自觉遵守） | **类型化 Lean 项**（不合法=0 容忍，§5 收益 1） |
| 推理结构 | 单链 CoT + 工具回调（长上下文堆叠） | **树**（OR/AND）+ 访问统计（§10：MCTS=算法焊点） |
| 中间验证 | 测试运行/人工读（弱、统计） | **kernel 校验 = 确定性终局**（reward 无噪声） |
| 学习信号 | 整轨奖励（GRPO/PPO）稀疏高方差 | 搜索回传 $V/Q$ **步级**监督（off-policy 天然） |
| 信用分配 | 轨迹级（长链稀释） | 步级（每步 $\hat Q$；§4） |
| 在线自适应 | 无（冻结推理） | v1 无；**v2 有**（TTT：调用期内更新参数） |
| 长任务能力 | 强在“扫描/扳手”广度；深层形式推理弱 | 强在“深层形式证明/抽象”；广度靠工具原语 |
| 可训练性（自改进） | 用户 RL 外部；重训大模型 | 自身 RTTT/rollout 数据闭环：数据→SFT/GRPO/TTT |

## 2.2 各自“擅长”的任务切片（诚实）

- **LLM agent 优**：需求不精确、反馈模糊、需要大量“读-试-修”的粗粒度工程（web 编写、集成、数据管道、Lean 项目脚手架/编译错误修复）。
- **本管线优**：**verifier-grounded** 的问题——证明与**可判定终局**（Lean kernel、test-with-assertion、数学断言、数据科学“曲线/统计检验”）；任务空间为**树状分解**且每步可校验。

## 2.3 融合（推荐的实际形态：harness 分工）

```
〔外层〕LLM agent（deepseek 等）：任务分解/上下文规划/粗修 （低成本、广度）
        │ 把“子问题”下放为 定理/断言/效果原语
〔内核〕reap-mcts-lean v1/v2：形式验证环（树×值×LLM 内核策略+TTT）
        │ 返回：证明了/反例/诊断（结构化观测）
        └ 外层将观测合回计划 → 继续（§5 的 Eff 通道 = 这个边界的类型化接口）
```
即：**外循环 = agent（语言+工具）；内循环 = P-V-MCTS+TTT（形式+在线）**。
这一分工是 §4“三层桥接”与 §8“数学驱动技能涌现”协同的自然落点：外层提供“情境理解”，内层提供“逐步监督与技能学习”。

## 2.4 一个可分辨的度量（落地建议）

$$R_{\text{agent}} = \alpha \cdot \underbrace{\mathrm{solve@B}}_{\text{形式}}{\color{gray}+\beta \cdot \mathrm{util}_{\text{tools}}}+\gamma \cdot \mathrm{depth}_{\text{ladder}}$$
按维度上报（§8 的 A/B/C/D），用以判断“我们的 agent 是否真的具备 agentic 技能”而非“只是搜索器”。
