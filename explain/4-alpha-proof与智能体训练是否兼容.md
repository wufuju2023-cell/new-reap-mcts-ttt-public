# MCTS 策略/价值管线 vs 智能体工具调用：训练流程的兼容性严格分析

## 0. 先把两套管线形式化

### P-V 管线（AlphaZero/AlphaProof 谱系）

- 作用对象：状态-动作对 $(s,a)$，动作空间 $\mathcal{A}(s)$ 离散有限；动作 $a$（Lean 词法 tactic 或“调工具”）有一个**先验分布** $\pi_\theta(a\mid s)$（策略头）、状态价值 $V_\phi(s)$（值头），共享骨干双头；
- 学习信号：**搜索的产物**（改进后的 visit 分布、反向传播的价值 $Q$），训练目标：

$$\mathcal{L}_{\mathrm{PV}}=\underbrace{\lambda_p\,(-\pi^\mathrm{search}\log \pi_\theta)}_{\text{策略蒸馏（搜索改进）}}+\underbrace{\lambda_v\,\big(V_\phi(s)-Q_\mathrm{search}(s)\big)^2}_{\text{价值回归（搜索值）}}$$

- 数据生成者：**树搜索本身**（PUCT 选择、每次扩展与值回传都由系统内部控制）——搜索是学习过程的一部分，**行为策略 $\neq$ 当前参数**。

### 工具调用智能体管线（GPT-4.o/DeepResearch 型）

- 作用对象：**token 序列**策略 $\pi_\theta(\cdot|\text{history})$，工具调用 = 一段结构化文本生成（JSON 调用），环境（工具引擎/检索/代码执行）返回结果文本；
- 学习信号：**整轨结果奖励** $r(\tau)$（末端/稀疏），训练目标（GRPO/PPO 类）：

$$\mathcal{L}_{\rm agent}=\mathbb{E}_{\pi_\theta}\big[\min(\rho_t\,\hat A_t,\ \mathrm{clip}(\rho_t)\hat A_t)\big]+\beta\,\mathrm{KL}[\pi_\theta\|\pi_{\rm ref}]$$

- 数据生成者：**原始策略自采样**（生成式 RL 的标准循环：采样→打分→更新），无独立搜索层——搜索只作为**数据合成器**（如 STaR/ToT），不在训练信号内部。

## 1. 四个严格差异（“不兼容感”的来源）

| 维度 | P-V 管线 | Agent 管线 | 冲突点 |
|---|---|---|---|
| **动作空间** | 紧凑、离散、有限、每次一个决策 | 高维 token 序列动作（含工具参数） | 价值头 $V$ 天然在“状态”上；agent 无“状态”，只有“上下文” |
| **价值信号** | 值头与策略头**联合训练**（共享表示），且**由搜索内部产生** | 价值 = 外置 RM/critic（独立训练、冻结），或 DPO 隐式 | 联合 vs 解耦的梯度几何不同 |
| **行为策略** | 搜索的 visit 分布（**off-policy 子过程**） | 采样策略 == 更新策略（on-policy） | **P-V 训练天然 off-policy**，agent RL 要求 on-policy 基准/重要性校正 |
| **信用分配** | 每步有显式的 $\hat Q$（从搜索回传） | 整轨一个 $r$；每个 token 的梯度通过 $\hat A_t$ 端到端 | 前者是“步级强监督”，后者是“轨迹级弱监督” |

## 2. 是否“根本不兼容”？——否，但需要三层桥接

**严格结论**：两者在**梯度几何与数据生成机器**上不同（见 §1），但它们共享同一骨干（一个生成式 transformer），并且**在 action/state 表示上可以完全同构**——只要把“工具调用”定义为动作：

- 动作 $a$ = `调用(lean_check | lean_search | python_code | retrieve | 存入库)` + 参数（把工具调用参数看作 token 生成）；
- 转移 $T(s,a)=s'$ = 工具执行确定结果（Lean 校验给 ok/error/parse/timeout；python 给 stdout/异常）——这正是搜索引擎的“环境”；
- 于是 **P-V 管线就是“带搜索结构的 agent 工具调用器”，agent 管线是“无搜索结构的 P-V 特例”**（no-tree single-rollout）。

**不兼容的真正点**：并非同一个模型不能在两套里复用，而是**训练制度**上：

1. **搜索数据是 off-policy 的**，直接喂给 GRPO 型 agent 训练会引入“策略蒸馏 gap”；
2. **值头 + 策略头联合训练**要求**共享学习信号**（搜索值 $\hat Q$），agent 的 RM/critic 是独立的——混用后价值头与策略头不同步；
3. **工具调用 token 级策略**（生成参数 JSON，长度变动）与**搜索节点级决策**（取 1 个可执行动作）二者需要 **token 解码限制（grammar/约束解码）与状态化执行**的桥接（典型做法：约束解码把生成结果切成 $a$，Lean 验证回传 $s'$）。

## 3. 现代系统工程中如何桥接（实际上这正发生在 AlphaProof 类系统里）

可行的混合训练制度（**三层**）：

### 第 1 层：数据合成（search 作为生成器）

- 用 P-V 网（策略+值）跑 MCTS（每节点 = 一个真实工具调用），得到：(a) 搜索蒸馏目标 $\pi^{\rm search}$；(b) roll-out 轨迹 $\tau$ 与结果值。

### 第 2 层：策略学习（agent 型 RL 对合成数据）

- 对 roll-out 轨迹执行 GRPO/PPO（设置重要性率 $\rho=\pi_{\rm new}/\pi_{\rm old}$ 时用**搜索的 visit 分布**作为行为基线而不是 $\pi_{\rm old}$——即引入“search off-policy 校正”）：

$$A_t=\big(r(\tau)-V_{\rm search}(s_t)\big)\ \text{（search 提供的 per-step 值代替 critic）}$$

- 关键兼容设计：**值头不另训，直接复用搜索产生 $\hat Q$ 对其做回归**（$V_\phi$ → $\hat Q_{\rm search}$）；策略头用 $\pi^{\rm search}$ 蒸馏。这样搜索、agent 训练与值头更新**共享一套数据管线**——这正是 DeepSeek-Prover/AlphaProof 的“search 与 RL 交叠更新”的机制。

### 第 3 层：工具-状态正则

- 在采样/训练时对工具调用做**结构化生成**（JSON schema 的 grammar 约束）使 $\mathcal{A}(s)$ 变得紧凑可搜索；工具反馈转写为 $s'$，让“调用工具”这一动作与 P-V 的“tactic”享受同等的搜索+价值监督。

## 4. 明确点出“不兼容”的边界（什么情况下两者真的不能共生）

1. 若把搜索层当作**研究外循环**（只生成数据），而训练是**纯 on-policy GRPO**（不校正 off-policy），那么 P-V 的**价值信号丢失** → 训练后的策略与搜索策略差距 = 蒸馏误差 → “搜索改善的收益”被吞掉（**这就是很多 MCTS+LLM 系统“搜索有效但模型权重提升无效”的原因**）。
2. 若价值头与策略头**不共享调整**（一个在搜索中更新、一个在后台独立 RL），梯度几何脱节 → 模型端出现“价值过时”与震荡。
3. 若工具调用不约束到 $\mathcal{A}(s)$ 中（自由文本 JSON），则搜索树不可复用 → 回到“单轨 agent”形态，**与 P-V 的组合解空间减半**。

## 5. 结论

- **本质不同**：P-V 管线是“**搜索增强的步级价值监督**”（off-policy、步级、联合价值-策略平衡），agent 管线是“**整轨奖励的策略梯度**”（on-policy、轨迹级、外置 RM）——二者**不能自动互通**。
- **工程兼容条件**：
  1. 以“搜索作为数据合成器 + 策略蒸馏”桥接信号；
  2. 以“$V_\phi$ 回归 search-$\hat Q$ + 用 search 价值做优势基准”桥接价值与 agent-advantage；
  3. 以“对工具调用做状态化/结构化约束”桥接动作空间。
- 满足这三条，**同一骨干可以同时学习“搜索路径”与“agent 行为”**，且每一条的策略-价值-搜索闭环都闭合——这正是本项目路线中“strategy-head/priors + RTTT 在线价值头 + harness（工具调用）”的实现可行性基础。

> **一句话**：不是不能共存，而是**不能“不桥接就共存”**——桥接方案必须有“搜索作先验/数据、agent 作策略/工具、价值作共享监督”的显式三层结构，而我们把这一结构作为 V1-1 的主设计目标。
