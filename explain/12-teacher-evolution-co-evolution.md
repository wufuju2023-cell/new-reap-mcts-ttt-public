# 12｜教师进化与师生共进化：AlphaEvolve / OpenEvolve 参照下的全自动自改进

> 归档：把教师（出题/课程/评价器）也纳入进化式自更新，与学生的 RTTT 形成“相互 self-play”。
> 参考：AlphaEvolve（程序进化 + LLM 编辑 + 评估器 + rollback + 库沉淀）与 OpenEvolve（开源框架形态）。

## 0. 问题陈述

先前架构中“教师 → 学生”是**单方向耦合**（教师按固定 prompt/规则出题，只调整难度窗口）。若教师也能“自学习”：

$$\tau_{t+1} \leftarrow \mathrm{evolve}\big(\tau_t;\ \text{fitness} = \text{学生进步函数}\big)$$

则系统成为**双主体共进化**（teacher–student co-evolution），期望达到“学生的学习和教师的教学同时自动改进”的全自动循环——这正是 AlphaGo Zero 自博弈哲学在证明域的**第二个实体**（把“对手”职责置于一个可进化的教师身上）。

## 1. 形式化：双主体收益与不动点

设：

- 状态 = 库 $L_t$、难度地形 $D_t$、学生参数 $\theta_t$、教师策略 $\tau_t$（出题分布 $q_\tau(p)$、难度窗口、提示风格/算子权重）；
- **学生收益**：$$J_s(\theta; \tau) = \mathbb{E}_{p\sim q_\tau}\left[\mathrm{solve@}B(\theta, p)\right]$$
- **教师收益**（关键设计）：教师应最大化“**学习进步（learning progress）**”而非单纯难度：
$$J_t(\tau; \theta) = \mathbb{E}_{p\sim q_\tau}\Big[\underbrace{\Delta\,\mathrm{solve@}B(\theta,p)}_{\text{学生进步}}\Big] - \lambda_d\cdot\big(\mathrm{Diff}(p) \text{ 与可解带偏离}\big)$$
  其中 $\mathrm{Diff}(p)\in[0.5,0.9]$ 的“恰好够得着”带是正则项（防出题漂移）；
- **共进化稳定点**（教师-学生不动点）：$(\theta^\*, \tau^\*)$ 满足：$\theta^\*$ 已是 $\tau^\*$ 分布上的局部最优解法、$\tau^\*$ 已找不到能再提升 $J_t$ 的出题变异——这正是“Level-1 共同演化均衡”。

## 2. AlphaEvolve 的机制映射

| AlphaEvolve 组件 | 本方案对应物 |
|---|---|
| LLM 作为“程序编辑器” | 教师 = **prompt/规则/算子权重向量**（个体），LLM 修改它 |
| evaluator（得分器） | 学生评估器 = $\Delta \mathrm{solve@}B$ / $\Delta d_g$（由验证器 + rollouts 计算） |
| 进化循环（变异/交叉/rollback） | 教师池进化：变异（温度/题型压力/概念稀疏度）、交叉（混合教师） |
| 并行 & 预算管理 | 教师 fitness 的评估只发生在**少量学生代**上（低频；见 §3 时间尺度） |
| 库沉淀 | 教师池保留“高 LP 教师变体”（进化库），学生侧库照旧 |

AlphaEvolve 的关键教训适用于我们：

1. **评估器必须是“真阳性敏感”**的——它依据**验证结果**而非模型自评（我们正好用 kernel 与 $d_g$）；
2. **回滚**用于“过度变异”的教师个体（出题太难/太偏 → fitness 差 → 丢弃）；
3. **进化与推理并行异构**（meta level 开销小 ⟷ 学生代开销大——必须错峰）。

## 3. 三层时间尺度（工程正确性核心）

```
微观（每验证事件） : 学生 RTTT（θ/φ 在线一步更新）
中观（每 10–50 题）: 教师进化  — fitness 用“当前学生代”做 5–10 题迷你评估
宏观（每个学生代） : 教师评估器重建  — 用新学生代重新标定 Diff/难度，刷新教师池
```

- 教师进化**不占用学生训练资源**（fitness 评估 = 学生推理，可冻结学生代，用旧代评估 → “student-agnostic evaluation”）；
- 这避免了双主体共演化的经典病：**co-adaptive pathology**（教师与学生都朝彼此“假进步”点移动）。

## 4. 共演化的主要风险与严格对策

| 风险 | 机制 | 对策 |
|---|---|---|
| **度量绑架** | 教师最大化 LP，但 LP 有滞后/噪声 | 用 5–10 个样本求平均 + 惩罚“解不出”教师（Diff 超带） |
| **co-adaptive drift** | 教师-学生共同漂移（出“学生恰好会做但不是真进步”的题） | **定期冻结学生**：教师 fitness 用“冻结学生”评估；学生每隔 $G$ 代重建一次分布 |
| **教师过拟合学生** | 教师学会“刷题型”而非“引概念” | 奖励中强制 $\Delta d_g$（抽象深度）分量（教师必须出让“新概念可进入库”） |
| **进化成本爆炸** | fitness 评估要学生推理 | 迷你评估（5–10 题，$B$ 小）+ 单代只进化 top-2 教师 |
| **教师-库-学生三角失稳** | 教师出题依赖库，库增长依赖学生 | 教师的变异受“库可行性检查”（well-typed 过滤）约束——保持教师“只在可行域” |

## 5. 与自博弈（self-play）的理论关系

AlphaGo Zero 的 self-play 是**单实体算子的自参照**（策略与自己对弈）；我们的“双实体共进化”是它的**分体化推广**：

$$\text{self-play}:\ \theta \to \big(\text{solve self}\big) \Rightarrow \text{对象内部};$$
$$\text{co-evolution}:\ (\theta,\tau) \to \big(\text{solve } \tau\text{-题 }, \text{ 出 } \theta\text{-可学题}\big) \Rightarrow \text{双实体均衡}.$$

**严格判据**（可测）“到达全自动自提升”：

1. **LP 指标单调**（学生代间 solve@B 提升持续由教师变异带来）；
2. **教师多样性保持**（教师池每代的多样性熵不塌缩；否则意味着单策略自锁）；
3. **$d_g$ 增长**（教师出题确实出让“概念深度”，而非只在“题型”上循环）；
4. **稳定性**：教师 fitness 冻结学生评估 —— $\mathrm{LP}(G^\*)$ 跨版本学生≥阈值。

## 6. 结论

1. **可以**把教师也进化——且“教师进化 + 学生 RTTT”的共循环正是“全自动自提升”在本域的自然形态（把 AlphaGo Zero 的“对手”职能交给一个**进化中的教师**）；
2. 参照 AlphaEvolve/OpenEvolve，必须复制其三个要素：**验证器驱动的 fitness、变异-回滚算子、并行错峰的预算管理**——本方案里 fitness=学生进步（LP），对象=PPT 规格（prompt/规则/权重）而非程序，其余同理；
3. **严格风险对称**：教师进化必须防度量绑架与共漂移 → 冻结学生 + $\Delta d_g$ 分量 + Diff 正则（§4）；
4. **总体定位**：教师进化是“元层智能体”（meta-level agency）——它不直接解题，它优化“教学环境”；与学生的“解题智能”构成完整的学习-教学二象性…… 这正是“self-play 的数学域版本”的**完整形态**：不存在零和对手，但存在“教-学对手”。
